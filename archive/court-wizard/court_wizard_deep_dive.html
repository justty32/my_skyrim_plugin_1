⚙️ QuestEngine — 狀態機設計
  • 零 RE::/SKSE:: 依賴，only std + nlohmann-json。可在 Linux CLI 離線跑完整驗證。
  • Value = variant<double, bool, string>（SPEC §2）
  • validate() — 離線全文件結構驗證，收集所有錯誤（不 stop-at-first）
  • start() — 跑 on_start + 發 quest_start；resetState() 無副作用純清除（co-save Revert 用）
  • dispatchEvent(on, filter) — 驅動觸發器機器（SPEC §3.3）
  • checkTimers() — 到期計時器掃描；debugFireAllTimers() 無條件全觸發（F7 用）
  • Resumable 對話：presentNode display-only → submitChoice(idx) 推進，不阻塞主執行緒
  • hasStarted() — 持久化 lifecycle flag，存進 'QEST' blob，防 on_start 重複觸發
  • exportProgress() / importProgress() — 容錯序列化（壞 blob 降級不崩）
  • global.* — 跨任務 GlobalStore，reset_quest 不清除
  • random — PRF 演算法未定，暫不實作

Co-Save 持久化架構
💾 Central Dispatcher（ONE SetUniqueID per plugin）
SKSE 硬限制：SerializationInterface 每個 plugin 只允許一次 SetUniqueID + 一組 Save/Load/Revert callback（後者覆蓋前者）。 skyrim::cosave（CoSave.h）持有唯一 kPluginUniqueID = 'TPL1'，用 AddHandler 擴充出四個 record handler，在 OnLoad 裡以 GetNextRecordInfo 逐筆讀頭、依 4-char type 派發。
'QEST'
version 1
Quest Engine 進度：vars / objectives / activeDialogue / timers（絕對 game-hours）/ terminated / hasStarted flag + 系統 GlobalStore
'GNPC'
version 2
Generated NPC recipe（key + template plugin FormID + JSON recipe + 位置）。v2 多了 prior ref FormID，供 readopt 找舊 actor 而不 mint 新的
'PRGN'
version 1
Generated rooms/structures（key + kind + 自包含 recipe JSON + absolute origin + yaw + seed + cell/worldspace plugin FormID）
'GITM'
version 1
Generated items（WEAP/ARMO/MISC）recipe，rebuild 時重新鑄造並加回玩家背包（注意 H1 bug 已修：strip 舊的再加）
邏輯持久化原則：只存 recipe + plugin FormID（可 ResolveFormID 重映），絕不存 0xFF 動態 FormID。OnLoad 只 stage，RebuildStaged（kPostLoadGame 主執行緒）才鑄造。
程序生成系統
🏗️ Procgen.{h,cpp} — 室內/室外生成
  • Recipe 格式：templateId / gridStep / anchorDistance / seed / groundRule / shell / furniture / lights / clutter（含 scatter AABB）
  • GenerateInterior：在 anchor 前方 anchorDistance 單位處放置牆/地板/燈/家具/clutter；deterministic seed
  • GenerateStructure：外部模組城堡；groundRule（flatten_to_max / per_piece）用 RE::TES::GetLandHeight
  • RearrangeFurnishings：重排已追蹤的家具 ref，每次呼叫 cycle 一個佈局
  • ClearGenerated：Disable + SetDelete + 從 registry 移除，co-save 也清
  • RecipeToJson：自包含序列化，讓 co-save 重建可脫離原始 recipe file
  • M3 bug（已修）：spell 路徑 clutter scatter 參數丟失 → PieceSpec 現在保存 scatter 欄位
🧬 ProcgenNpc — NPC Form 生成
  • IFormFactory + Copy(template) 鑄新 TESNPC_；0xFF FormID 僅 session 內有效
  • Recipe：template / name / persist_key / scale / essential / level / sex
  • readopt 策略（v2）：OnLoad 先看 prior ref FormID，找得到就接管舊 actor（不 mint 不刪），找不到才 mint 新的 → 解決 within-session 存讀複製問題
  • 誠實說明：這是「邏輯持久化」。重載後 form 重建，舊 FormID 消失，quest alias / 其他 mod 的 ref 會失效。僅適合「同個位置重現同個 NPC」的場景。
  • 跨 session crash：完全關遊戲重開，.ess 中殘留的動態 actor 在 OnRevert 後找不到 base → crash。決定暫不修（根治需 hook BGSSaveLoadManager::Save，無現成 RELOCATION_ID）
⚔️ ProcgenItem — Item Form 生成（WEAP/ARMO/MISC）
  • WEAP/MISC：TESForm::Copy 是 no-op → 改用 component 深拷貝（TESValueForm/TESWeightForm/TESAttackDamageForm，以 static_cast 而非 As<T>）
  • ARMO：TESForm::Copy 有真實 override，可直接用
  • H1 bug（已修）：RebuildStaged 在重新鑄造前先 strip 玩家背包舊版本（依 key），不累加

C1 — Critical（已修）

H1 — High（已修）
ProcgenItem::RebuildStaged 每次讀檔重新鑄造 + AddObjectToContainer，沒有 RemoveItem → 每次讀檔物品倍增
修法：RebuildStaged 在 MintItem 前先對玩家背包做 best-effort RemoveItem（依 key），strip prior → 不累加。header doc 與 impl 現在一致（修 L3）。
H2 — High（已文件化，待深拷貝）
WEAP weaponData 淺拷貝，RangedData* 指標 alias → ranged 模板會 double-free

M1 — Medium（已修）
submitChoice 內 reset_quest 若重啟出新對話，守衛無條件清 activeDialogue，抹掉剛開的對話
